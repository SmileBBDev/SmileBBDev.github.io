**R-CNN → Fast R-CNN → Faster R-CNN → SSD → RetinaNet → YOLO** 순서로 <br> “왜 발전했는지”와 “어떻게 동작하는지” 학습

## Object Detection(객체 탐지) 이란?

한 이미지에서

1) 물체가 어디 있는지(박스: 회귀, Regression)

2) 그 물체가 무엇인지(분류: Classification)

이 **두 가지를 동시에** 해결하는 문제

“이 이미지 속에서 바나나(클래스)가 어디(Bounding Box) 있어?” 를 한번에 풀어야 하는 문제

---

### Object Detection 기본 원리 (초간단 버전)

**목표 :  사진 속에서 물체가 어디 있는지(박스), 무엇인지(라벨)** 찾는 것

이미지에서 물체를 찾으려면 2가지를 해야 함

1. **그림에서 물체가 있을 만한 위치를 찍기** → 이것이 Bounding Box (회귀)
2. **그 물체가 무엇인지 분류하기** → Cat, Dog, Person … (분류)

그래서 **Regression + Classification = Object Detection**



## R-CNN 세대의 발전 흐름 (왜 발전했는지 중심)

### R-CNN - 가장 원시적인 방식

>“영역을 따로따로 CNN에 넣으니 엄청 느림”

1. 이미지에서 영역 후보 2천개 뽑기 (Selective Search)
2. 각 후보를 CNN에 넣어서 “이게 물체냐?” 확인
    - 너무 느림 (2천개를 매번 CNN에 넣음)
    - 학습도 단계가 너무 많아서 복잡함

### Fast R-CNN - 적어도 CNN은 한 번만 돌리자!

>“CNN은 한 번만 돌려서 빨라졌지만, 영역 찾는 과정이 아직 느림”

- CNN **한 번만 돌리고** Feature Map 생성
- Feature Map 위에서 필요한 부분만 잘라서 분류
    - 훨씬 빠름
    - 하지만 Selective Search(영역 찾기)는 여전히 느림

### Faster R-CNN - 영역 찾는 것도 딥러닝으로!

>“영역 찾기까지 딥러닝으로 자동화 → 훨씬 빠르고 정확”

혁신: 영역 찾기도 CNN이 하자! → **RPN (Region Proposal Network)**

- Selective Search 제거
- RPN(Region Proposal Network)이 스스로 “여기 물체 있을 듯?” 하고 박스 제안

정확 + 빠름 = 강력한 2단계 모델

---

## SSD와 YOLO 계열 — 실시간 모델 (One-Stage Detection)

R-CNN 계열은 **2단계(two-stage)** 방식

1. 박스 찾고
2. 분류하는

이건 느림.

그래서 나옴 → **한 번에 끝내는 One-Stage 모델**

---

### SSD (Single Shot Detector) - 한 번에 예측 끝!

>“영역 찾기와 분류를 한 번에 처리 → 빠르지만 작은 물체는 약함”

👉 *싱글샷 = 이미지 한 번 보고 바로 박스+클래스 예측*

- 매우 빠름(실시간 가능)
- 작은 물체 탐지 정확도는 낮음


### 앵커 박스(Anchor Box)가 핵심!
앵커박스 = “미리 준비해둔 다양한 모양의 박스”
- 바나나는 가로로 길고
- 사람은 세로로 길고
- 자동차는 넓적하고

이렇게 **물체마다 모양이 다르니까**, 모델이 다양한 박스 형태를 미리 준비

그래서 이미지 곳곳에 대략 **8732개의 후보 박스**를 뿌려놓고

→ 그 중 “진짜 물체”만 걸러냄



---

### RetinaNet — 빠르면서도 정확하고 싶다!

>“SSD처럼 빠른데 정확도도 챙긴 모델 (Focal Loss 덕분)”

SSD처럼 **한 번에 예측** 👉 하지만 큰 문제 하나 있었음 = **클래스 불균형 문제**

- 배경이 너무 많고 물체는 적어서 학습이 잘 안 됨

해결책 = **Focal Loss**

- 어려운(헷갈리는) 데이터에 더 집중해서 학습하도록 함

결과

- 정확도 ↑
- 속도 유지

---

### YOLO - 가장 유명한 실시간 모델!

>“한 번만 보고 바로 예측 → 제일 빠른 탐지 모델”

YOLO = You Only Look Once

→ 진짜 이미지 한 번만 보고 바로 예측하는 급발진 모델

### YOLO 방식

1. 이미지를 격자(Grid)로 나눔
2. 각 격자가
    - 물체가 있는지
    - 박스는 어떤지
    - 무슨 클래스인지

한 번에 예측

엄청 빠름 (실시간 가능)

최근 버전은 정확도도 매우 좋아짐

### YOLO 버전 설명

- YOLO10 = 연구용
- YOLO11 = 실무용
- YOLO12 = Attention 더 넣은 확장형

---

## 평가 방식 (Regression, Classification이 왜 나왔는지)

### 1) 회귀(Regression) 평가: IoU

IoU = 예측 박스와 정답 박스가 얼마나 겹치는가

값이 높을수록 정확

### 2) 분류(Classification) 평가: Precision-Recall Curve

- Precision: 예측한 것 중에 맞춘 비율
- Recall: 실제 정답 중 얼마나 찾아냈는지

Detection에서는 PR-curve가 중요함

## 백본 / 헤드 구조 (전체 구조 이해 핵심)

Object Detection 모델은 3단계 구조

### 1) Backbone

👉 이미지에서 특징(feature) 뽑는 CNN (ResNet, VGG, CSPNet 등이 여기 들어감)

### 2) Neck

👉 특징을 좋게 만들기 (FPN, PAN, BiFPN 등)

→ 올라가며 추상적 특징, 내려오며 디테일 복구

### 3) Head

👉 **박스 회귀 + 클래스 분류**

최종 예측 담당

YOLO, SSD도 다 이 3단계 구조

**이미지에서 객체를 찾기 위해 다양한 모양 박스를 미리 뿌려놓고(CNN 특징 위에서), 그 중 진짜 물체를 찾아내는 방식이 Object Detection**

모델의 발전 방향은

- **더 빠르게** (→ YOLO, SSD)
- **더 정확하게** (→ Faster R-CNN, RetinaNet)
- **더 다양한 크기의 물체 잘 찾기** (→ FPN, YOLOv11, YOLOv12)

---


## **완전 이해되도록** Object Detection 전 과정을 **비유로만** 설명

이미지를 **큰 건물**이라고 생각하고

**건물 안에서 ‘고양이·강아지·사람’ 같은 물체(사람)를 찾아야 한다.**

이 건물(이미지) 어디에 어떤 사람이 있는지 찾아내! == Object Detection 을 뜻함


### 전체 흐름을 비유로...

| 모델 | 비유 |
| --- | --- |
| R-CNN | 방 2000개 직접 열어보기 |
| Fast R-CNN | CCTV 한 번 보고 필요한 방만 열어보기 |
| Faster R-CNN | CCTV가 자동으로 의심 방 표시해줌 |
| SSD | 바닥 전체에 8732개 센서 뿌려서 한 번에 탐지 |
| YOLO | 건물을 격자로 나누고 각 칸 담당자가 즉시 물체 보고 |

---

## R-CNN = *건물의 모든 방을 하나씩 직접 열어보는 탐정*

### 하는 일

1. 먼저 건물에 있는 **방 2000개를 대충 골라냄** (Selective Search)
2. **각 방(영역)을 직접 들어가서 확인**함 → CNN
3. “이 방에 강아지가 있나?”라고 하나씩 판단

### 문제

- 방이 2000개 → 하나씩 확인하니 **너무 느림**

**요약**

> “문을 2000개 열어보는 방식 → 정확은 하지만 너무 느림”
> 

---

## Fast R-CNN = 건물 전체 CCTV를 먼저 보고 필요한 방만 다시 확인하는 탐정

### 하는 일

1. 건물 전체를 **CCTV로 한 번만 훑음** (CNN 한 번)
2. CCTV 화면에서 방 번호만 확인해 들어감

    ➡ 훨씬 빨라짐

하지만 여전히 “방 후보 2000개 고르는 과정(Selective Search)”만은 느림

**요약**

> “일단 전체 CCTV를 한 번 보고, 필요한 방만 들어가는 방식.
> 
> 
> 빠르지만, 여전히 방 고르는 게 느려!”
> 

---

## Faster R-CNN = CCTV가 알아서 ‘의심스러운 방’을 자동으로 골라주는 시스템

### 혁신

Selective Search 제거 → 대신 CCTV(AI)가 자동으로 의심되는 방을 표시해줌

= **RPN(Region Proposal Network)**

탐정은 그 방만 확인하면 됨. 👉 더 빠르고 정확!

**요약**

> “CCTV가 스스로 ‘여기 수상함!’ 표시까지 달아줌 → 탐정은 확인만 하면 됨”
> 

---

## SSD = 건물 전체 바닥 곳곳에 작은 감지 센서 8,732개를 설치하는 방식

이제 아예 방 단위 조사가 아니라 **건물 바닥 전체에 수천 개의 센서를 뿌림**

👉 그 센서가 빠르게 알려줌

    - “여기 고양이 있을 확률 높아!”
    - “여긴 사람일 듯!”
    - “여긴 아무것도 없음!”


➡ 빠른 이유: 감지기가 자동으로 동시에 작동함 → *Single Shot*

**요약**

> “건물 바닥에 8천 개의 센서를 뿌려놓고, 한 번에 어디에 누가 있는지 알아냄 → 매우 빠름”
> 

---

## YOLO = 건물을 격자로 쪼개서 각 칸의 책임자를 배치하는 방식

YOLO는 센서를 뿌리는 방식이 아니라 건물을 바둑판처럼 나눔

예: 모든 칸이 동시에 말하니까 실시간급 속도가 나옴

- 7×7 그리드면 49개의 칸
- 각 칸의 책임자가 말함
    - “내 구역에 고양이 있다!”
    - “없다!”
    - “박스 크기는 이 정도!”

**요약**

> “건물을 49칸으로 나누고,
> 
> 
> 각 칸의 담당자가 ‘여기 사람!’ 하고 즉시 알려주는 방식 → 실시간 가능”
> 

---

## RetinaNet = 센서가 너무 많아 배경 오작동이 많길래 ‘중요한 신호만 강조하는 기술(Focal Loss)’ 추가

센서를 수천 개 깔아놓으면 대부분 공간은 “빈 방”이니까 자꾸 쓸데없는 신호가 많아져(=클래스 불균형 문제).

그래서 나온 해결책 → **Focal Loss** = “중요한(어려운) 감지 신호만 크게, 쉬운 신호는 작게!”

**요약**

> “잡음(빈 신호)이 너무 많아서, 중요한 신호 위주로 듣게 만든 방식”
>
