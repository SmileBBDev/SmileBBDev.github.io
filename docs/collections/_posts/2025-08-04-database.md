## RDBMS(Relation Data Base Management System)

관계형 데이터베이스(RDBMS)는 **대량의 데이터를 저장하고 공유**하기 위해 만들어진 시스템입니다.  
프로그래밍에서 변수를 정의하고 → 자료형 → 함수 → 클래스로 발전해온 것처럼, 데이터베이스도 유사한 구조를 가집니다.  

---

## 메모리와 데이터베이스
- **RAM**: 휘발성 메모리, 전원이 꺼지면 데이터가 사라짐 (Random Access Memory)  
- **ROM**: Read Only Memory, 읽기 전용  
- **CIMOS**: 시스템 설정 저장/수정 가능 (BIOS 설정 화면, F2로 진입)  

파일로 데이터를 저장하면 공유에 한계가 있어, 이를 해결하기 위해 DB가 등장  

---

## DB와 클래스의 유사성
- DB는 **행과 열**로 이루어져 있음  
- **행(record, tuple)** = 클래스의 인스턴스와 유사  
- **열(field)** = 클래스의 멤버변수와 유사  
- 리스트에 데이터를 `append` 하듯, DB도 행 단위로 데이터를 추가  

---

## 데이터 저장과 검색
- **순서 보장**: 데이터를 순서대로 저장  
- **Key 값 매핑**: 유일하고 중복 없는 키를 주소와 연결  
- **검색 속도 향상**: 인덱스를 별도로 만들어 정렬 후 빠른 검색 가능  
- **Binary Search**: 정렬된 데이터 기반으로 빠른 탐색  



## 데이터 타입
- 숫자형, 문자형, 날짜형, Binary, BLOB 등  
- 예: `int`, `varchar`, `char`, `short`  
- `varchar(10)`: 최대 10자까지 저장 가능, 초과 시 저장 불가  

---

## 정규화(Normalization)
데이터 중복을 방지하고 저장 공간을 절약하기 위한 과정

- **제1정규화**: 하나의 데이터에는 하나의 원자값만 저장  
- **제2정규화**: 복합키를 단일키로 변경, 부분 함수 종속 제거  
- **제3정규화**: 이행적 함수 종속 제거  
- **BCNF**: 결정자이면서 후보키 제거  
- **제4정규화**: 다치 종속 제거  
- **제5정규화**: 조인 종속성 이용  
- **역정규화**: 성능 향상을 위해 테이블을 다시 합치는 과정  


## 제약조건(Constraints)
- **default**: 기본값 설정  
- **check**: 값의 범위 제한  
- **PK(Primary Key)**: 유일한 값, 중복 불가, Null 불가  
- **FK(Foreign Key)**: 다른 테이블의 PK를 참조하여 관계 설정  
- **unique**: 중복 불가, Null 허용  

---

## Transaction (트랜잭션)
데이터 신뢰성을 보장하는 단위 작업

- **commit**: 변경사항을 DB에 반영  
- **rollback**: 오류 발생 시 이전 상태로 되돌림 (save point까지)  
- **save point**: 특정 지점까지 실행 상태 저장  

예: 계좌이체 중 오류 발생 시 전체 작업을 취소하고 원상태로 복구  


## View, Trigger, Event
- **View**: 가상 테이블, 실제 저장 공간 없음 (복잡한 select문을 단순화)  
- **Trigger**: 특정 테이블에 변화가 생기면 자동으로 다른 작업 실행  
  - 예: 성적 변경 시 총점과 평균 자동 재계산  
- **Event**: 규칙적으로 실행되는 작업  
  - 예: 게임 접속 시 보상 지급  


---

## DB 명령어
- **DDL (Data Definition Language)**: 테이블 생성/삭제/수정  
  - `create`, `drop`, `alter`, `truncate`  
- **DML (Data Manipulation Language)**: 데이터 조작 (CRUD)  
  - `insert`, `select`, `update`, `delete`  
- **DCL (Data Control Language)**: 권한 제어  
  - `grant`, `revoke`  
- **DQL (Data Query Language)**: 데이터 조회  
  - `select`  
- **TCL (Transaction Control Language)**: 트랜잭션 제어  
  - `commit`, `rollback`, `savepoint`  


## SQL 예시
```sql
-- 국어, 수학, 영어 총합과 평균
SELECT SUM(kor), SUM(mat), SUM(eng) FROM student;
SELECT AVG(kor), AVG(mat), AVG(eng) FROM student;

-- 총점과 평균
SELECT SUM(kor+mat+eng), AVG(kor+mat+eng) FROM student;

-- NULL 처리
SELECT NAME, COALESCE(kor,0) + COALESCE(mat,0) + COALESCE(eng,0) FROM student;

-- 학교별 총점 합계
SELECT sc.schoolname, SUM(IFNULL(kor,0)+IFNULL(mat,0)+IFNULL(eng,0)) AS "총점 합계"
FROM student st INNER JOIN school sc ON st.schoolcode = sc.schoolcode
GROUP BY sc.schoolcode;

-- 변수에 대입
SELECT schoolcode INTO @abc
FROM school
WHERE schoolname = "충주여자고등학교";

SELECT SUM(kor), SUM(mat), SUM(eng)
FROM student
WHERE schoolcode = @abc;
```

## 정리
- RDBMS는 **대량의 데이터를 저장하고 공유**하기 위한 시스템  
- **행(record)**은 클래스 인스턴스, **열(field)**은 멤버변수와 유사  
- **정규화**로 중복을 방지하고 저장 공간을 절약  
- **제약조건**과 **트랜잭션**으로 데이터 무결성과 신뢰성 확보  
- **View, Trigger, Event**로 복잡한 작업을 단순화하고 자동화
