## 데이터베이스 핵심 개념 정리: 공유 · 관계 · 검색

데이터베이스는 **대량의 데이터를 저장하고 공유**하기 위해 만들어진 시스템입니다.  
관계형 데이터베이스(RDBMS)는 데이터를 **행과 열**로 관리하며, **중복을 최소화하고 무결성을 보장**하는 구조를 갖습니다.  

---

## 🔑 데이터베이스 3대 키워드

### 1. 공유 (Sharing)
- DB에 접속하기 위해 필요한 5가지 정보  
  - **IP, Port, ID, Password, DB명**  
- 클라우드에 DB를 설치하는 이유: 여러 사용자가 공동으로 접속하기 위함  

### 2. 관계 (Relationship)
- 테이블 간 관계는 **PK(Primary Key)**와 **FK(Foreign Key)**로 맺음  
- 제약조건(Constraints)  
  - **No Action**: 무결성 원칙 위배 시 동작 불가  
  - **Restrict**: FK가 참조 중이면 PK 삭제 불가  
  - **Cascade**: 참조 데이터까지 연쇄 삭제  
  - **Set Null**: 관계가 끊어지면 FK를 Null로 변경  
- 관계 유형  
  - **1:1 관계**: 관리 복잡 시 테이블 분리 후 연결  
  - **1:N 관계**: 하나의 데이터가 여러 데이터와 연결  
  - **N:M 관계**: 직접 연결 불가, 중간 테이블 필요  
- **Join**: 여러 테이블 데이터를 연결해 조회  
  - Inner Join, Left Join, Right Join, Full Join  
- **Trigger**: 테이블 변화 시 자동 실행 (Insert, Update, Delete)  

### 3. 검색 (Search)
- **인덱스(Index)**: B-Tree 기반, 빠른 검색을 위해 별도 공간에 생성  
- PK와 Unique Key 지정 시 자동 인덱스 생성  
- 인덱스는 많을수록 성능 저하와 공간 낭비 → 필요한 곳에만 설정  
- Insert/Update/Delete 시마다 인덱스 재구성 필요

## 데이터베이스 설계 5단계

| 단계 | 명칭 | 핵심내용 |
| --- | --- | --- |
| 1단계 | 요구사항 분석 | 무엇을 저장할 것인가? 어떤 기능이 필요한가? |
| 2단계 | 개념적 설계 | 현실 세계를 ERD(Entity-Relationship Diagram)로 모델링 |
| 3단계 | 논리적 설계 | DBMS 독립적인 정규화된 테이블 구조로 변환 |
| 4단계 | 물리적 설계 | DBMS에 맞춰 성능 최적화(인덱스, 파티션 등) 적용 |
| 5단계 | 구현 및 유지보수 | 실제 SQL로 테이블 생성, 테스트, 운영, 튜닝 |


## 🎯 설계 목표와 구현 전략

| 목표 | 기술적 접근 | 구현 전략 |
| --- | --- | --- |
| 무결성 | 정규화, 제약조건, 트랜잭션 | CHECK, FK, 트리거, ACID |
| 유연성 | 정규화, View, JSON | 설계 분리, 동적 컬럼 |
| 확장성 | 파티셔닝, 샤딩, 모듈화 | 수평/수직 확장, 마이크로서비스 연계 |

- **무결성**: PK, FK, Unique Key, Default, Check / 트랜잭션 단위 실행  
- **유연성**: View(가상 테이블), JSON(필드 단계에서 유연성 확보)  
- **확장성**:  
  - **파티셔닝**: 범주형/날짜 기준으로 테이블 분리 → 검색 속도 향상  
  - **샤딩**: 여러 시스템에 분산 저장 → 장애 발생 시 복원 가능  
  - **모듈화**: DB를 나눠 관리 용이 → 파이썬 모듈화와 유사

## 개념 복습

- **프로시저(Stored Procedure)**: 여러 명령어를 묶어 함수처럼 호출, 트래픽 감소, 공동 작업에 유리  
- **View**: 물리적 구조 변경 없이 유연성 확보  
- **Trigger**: 데이터 변경 시 자동 실행  
- **Event**: 지정된 간격/날짜에 자동 실행  
- **JSON**: Key-Value 구조, 파이썬 딕셔너리와 동일

## ERD와 관계

- **1:1 관계**  
- **1:N 관계**  
- **N:M 관계**: 중간 테이블 필요 (예: 대여자 테이블 – 대여 테이블 – 비디오 목록 테이블)

## 정리
데이터베이스는 **공유, 관계, 검색**이라는 3대 키워드를 중심으로 설계
- 공유: 접속 정보(IP, Port, ID, Password, DB)  
- 관계: PK-FK, 제약조건, Join, Trigger  
- 검색: 인덱스, 정렬, 최적화  

설계는 **요구사항 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현 및 유지보수** 단계로 진행되며, 무결성·유연성·확장성을 확보하기 위해 **정규화, 제약조건, 트랜잭션, View, JSON, 파티셔닝, 샤딩, 모듈화** 등을 활용
