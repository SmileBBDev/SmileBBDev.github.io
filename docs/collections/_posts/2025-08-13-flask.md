## 가장 가벼운 경량 웹 프레임워크, **Flask**로 웹 제작하기

웹 개발을 배우면서 꼭 알아야 할 핵심 요소는 **HTML, CSS, JavaScript, Flask** 그리고 **웹 요청 흐름**입니다.  
이번 글에서는 이들의 역할과 흐름을 정리해보겠습니다  

---

## 웹 프론트엔드 구성

| 구성 요소 | 역할 |
| --- | --- |
| **HTML** | 콘텐츠의 구조를 정의 (태그로 작성) |
| **CSS** | 콘텐츠의 스타일을 지정 (색상, 크기, 배치 등) |
| **JavaScript** | 동적인 기능 구현 (값 변화, 이벤트 처리 등) |

---

## JavaScript 핵심 개념

- **변수와 데이터 타입**: `let`, `const`, `var`로 선언하며 다양한 타입 존재 (string, number, boolean 등)  
- **기본 자료구조**:  
  - `Object` → Python의 `dict`와 유사  
  - `Array` → Python의 `list`와 유사  
- **통신 기반**: 서버와 데이터를 주고받기 위해 사용  
- **데이터 포맷**: 주로 `JSON` (JavaScript Object Notation) 형태로 주고받음  

---

## Flask의 역할 (백엔드 웹 서버)

| 기능 | 설명 |
| --- | --- |
| **HTML 생성** | 정적인 페이지를 렌더링 |
| **동적 콘텐츠 처리** | DB에서 데이터를 가져와 HTML에 삽입 |
| **서버 사이드 렌더링** | 서버에서 HTML을 완성해 클라이언트에 전달 |
| **템플릿 엔진 (Jinja)** | HTML 안에 Python 변수/로직을 삽입해 동적 페이지 생성 |

---

## Jinja란?

- Flask에서 사용하는 **템플릿 엔진**  
- 서버 측에서 데이터를 HTML에 삽입  
- HTML 안에 **Python 변수나 제어문**을 삽입할 수 있게 해줍니다  


{% raw %}
예: {{ username }} → 서버에서 username 값을 넣어 클라이언트에 전달
{% endraw %}


### 템플릿 상속 문법  
```jinja
{% raw %}
{% block content %}
    {{ variable }}
{% endblock %}
{% endraw %}

```

{% raw %}

| 문법 | 설명 |
| --- | --- |
| `{% block name %}` | 해당 영역을 다른 템플릿에서 덮어쓸 수 있게 정의 |
| `{% endblock %}` | block의 끝을 표시 |
| `{{ variable }}` | Python 변수 값을 삽입 |
| `{% ... %}` | 제어문, 반복문, 조건문 등 |

{% endraw %}

## 웹 요청 흐름

| 개념 | 설명 |
| --- | --- |
| **Request** | 클라이언트가 서버에 보내는 요청 (URL, form 등) |
| **Response** | 서버가 클라이언트에게 보내는 응답 (HTML, JSON 등) |
| **Flask의 request 객체** | 요청 데이터를 자동으로 파싱해 사용 가능 (`request.form`, `request.args`) |
| **Flask의 response 객체** | 응답을 구성해 클라이언트에 전달 (`render_template`, `jsonify`) |

## 쿠키(Cookie)의 역할과 특징

쿠키는 **웹 브라우저에 저장되는 작은 데이터 조각**으로,  
클라이언트(사용자)의 컴퓨터에 저장되어 **웹 서버와의 통신에 활용**됩니다.

### 주요 목적
- 사용자 식별 (로그인 상태 유지, 세션 관리)  
- 환경 설정 저장 (언어, 테마 등)  
- 트래킹 (방문 기록, 광고 타겟팅)  
- 요청 간 정보 유지 (HTTP는 stateless → 쿠키로 상태 유지)  

### 저장 위치
- 클라이언트 브라우저가 관리  
- 서버는 `Set-Cookie` 헤더로 전달 → 클라이언트는 요청 시 `Cookie` 헤더에 포함  

### 주의사항
- DB 저장용이 아님 (임시 저장소 성격)  
- 비밀번호, 개인정보는 절대 쿠키에 저장하지 않음  
- 대신 **세션 ID**를 쿠키에 저장하고 실제 데이터는 서버 DB/메모리에 보관  

### 보안 속성
- `HttpOnly`, `Secure`, `SameSite` 옵션으로 보안 강화  
- 민감한 정보는 토큰/세션 ID로 간접 처리

## 전체 흐름 요약

```
Client 요청
   ↓
GET / POST 방식
   ↓
Flask 서버 (request/response 처리)
   ↓
CRUD로 DB 접근
   ↓
크롤링 애플리케이션 실행 (필요 시)
   ↓
데이터 가공 및 HTML 생성
   ↓
Client에게 응답 (Response or Redirect)
```

## 요청과 응답 (Request & Response)

| 개념 | 설명 |
| --- | --- |
| **Request** | 클라이언트가 서버에 보내는 요청 (URL 입력, form 제출) |
| **GET** | 데이터를 요청할 때 사용 (예: 페이지 조회) |
| **POST** | 데이터를 서버에 보낼 때 사용 (예: form 제출) |
| **Response** | 서버가 클라이언트에게 보내는 응답 (HTML, JSON 등) |
| **Redirect** | 다른 URL로 클라이언트를 이동시킴 (`redirect('/home')`) |

---

## Flask와 DB (CRUD)

| 작업 | 설명 |
| --- | --- |
| **Create** | 새로운 데이터 생성 (예: 사용자 등록) |
| **Read** | 데이터 조회 (예: 게시글 목록 보기) |
| **Update** | 기존 데이터 수정 (예: 프로필 변경) |
| **Delete** | 데이터 삭제 (예: 게시글 삭제) |

- Flask는 ORM (예: SQLAlchemy) 또는 직접 SQL을 통해 CRUD 수행  
- 응답 시 DB에서 필요한 데이터를 가져와 HTML에 삽입  

---

## 크롤링 애플리케이션

- 외부 웹사이트에서 데이터를 수집  
- Flask 내부 또는 별도 모듈로 실행  
- 수집된 데이터를 DB에 저장하거나 바로 클라이언트에 전달  

---

## 저장 기능이 없는 이유?

- 일부 요청은 **임시 데이터 처리**만 필요  
- 저장하지 않으면 **응답 속도 향상**  
- 예: 크롤링 결과를 화면에만 보여주고 DB에는 저장하지 않음  

---

## 클라이언트 화면에 보여지는 방식

- Flask가 HTML을 생성 (`render_template`)  
- Jinja 템플릿으로 동적 데이터 삽입  
- 최종 HTML을 클라이언트에게 응답
