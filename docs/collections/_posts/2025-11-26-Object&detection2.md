## 앵커박스(Anchor Box)
“다양한 크기의 상자 샘플을 미리 깔아놓기”
### 비유

> 너에게 “이 건물 안에서 고양이·사람·개를 찾아라”라고 했다
> 

그런데…

- 고양이는 가로로 길쭉
- 사람은 세로로 길쭉
- 개는 정사각형

이렇게 **모양이 다 다르잖아?** 그래서 탐정(모델)이 바로 찾기 어려워 그래서 어떻게 하냐면?

건물 바닥 곳곳에 **여러 모양의 빈 상자**(앵커박스)를 미리 올려둔다.
- 세로 긴 상자
- 가로 넓은 상자
- 정사각형 상자
    
< 실제 탐지 과정 비유 >
1. 바닥 8732곳에 상자를 쫙 깔아 놓고
2. 각 상자에게 이렇게 물어봄: **“너 안에 물체 있을 것 같아?”**
3. 그러면 상자들이 이런 식으로 대답함:
- “여기 사람 있는 것 같은데요?”
- “난 비었어요!”
- “여긴 강아지요!”




### ✔ 요약

> **앵커박스**는 “미리 다양한 형태의 빈 상자를 곳곳에 깔아두고, <br> 그 안에 물체가 있을지를 빠르게 평가하는 장치”
>

## IoU (Intersection over Union)

### 비유
> “두 사람이 그린 동물 위치가 얼마나 겹치냐”
> 

너랑 친구가 같은 지도 위에 “강아지 위치”를 네모로 표시했다고 하자.

IoU = 두 네모가 **얼마나 겹치는지의 비율**

- 완전히 겹침 → IoU = 1 (100%)
- 반만 겹침 → IoU = 0.5 (50%)
- 거의 안 겹침 → IoU = 0
- 전혀 다르면 → 0

 ✔ 왜 중요한가?

Object Detection은 **예측 박스가 정답 박스와 얼마나 비슷하게 위치했는지**를 봐야 한다.

즉, IoU는 **“너가 찾은 위치가 얼마나 정확한가?” 를 평가하는 점수**

## Precision–Recall Curve

### 비유
> “경찰이 도둑을 얼마나 잘 잡는지 평가하는 두 기준”
> 

건물에 도둑이 10명 있다고 하자.

경찰이 도둑 잡기 성능을 평가해야 함.

### Precision (정밀도)

> “경찰이 잡은 사람 중에서 진짜 도둑이 몇 명이냐”
> 

- 10명 잡았는데 8명이 도둑 → Precision 80%
- 10명 잡았는데 2명이 도둑 → Precision 20%


### Recall (재현율)

> “실제 도둑 10명 중 경찰이 몇 명을 잡았냐”
> 

- 10명 중 9명 잡음 → Recall 90%
- 10명 중 3명 잡음 → Recall 30%


### Object Detection에서 왜 중요?

탐지 모델은 둘 다 고려해야 똑똑한 모델!

- 너무 많이 잡으면(박스 막 뿌림) → Recall 높고 Precision 낮아짐
- 너무 깐깐하게 잡으면 → Precision 높고 Recall 낮아짐

## YOLO 


YOLO를 경찰 부대로 생각하자 — “경찰 부대의 진화 과정 비유”

### **< 버전 차이 >**
### 🚓 YOLOv1–3 = 초창기 경찰

- 빠르긴 한데
- 멀리 있는 작은 도둑을 못 봄
- 어두운 데 약함



### 🚓 YOLOv4–5 = 기술 경찰

- CCTV 화질 좋아짐
- 멀리 있는 도둑도 잘 봄
- 여러 크기 물체 잘 잡음(FPN/PAN)

→ 실무에서 많이 쓰였던 세대



### 🚓 YOLOv7–8 = 특수부대

- 여러 크기 물체 처리 고도화
- 속도·정확도 둘 다 업그레이드
- 확장성 좋아짐



### 🚓 YOLOv10 = 연구소에서 만든 실험형

- 연구 논문용
- “객체 탐지 성능을 어떻게 더 올릴까?”
- 최신 아이디어 다 넣은 실험 버전



### 🚓 YOLOv11 = 산업용 프로 경찰

- “실무에서 바로 쓰기 좋은 버전”
- 속도·정확도 균형
- 실제 CCTV, 자동차, 공장에 바로 적용 가능



### 🚓 YOLOv12 = 집중력 + 지능 강화된 요원

- Attention 기술 도입
- 더 작은 물체, 복잡한 환경도 잘 잡음
- 실전에서 더 안정적


### ✔ 요약

> YOLO는 경찰 부대가 계속 업그레이드되면서
더 빠르고, 더 정확하고, 더 똑똑해지는 과정
>
