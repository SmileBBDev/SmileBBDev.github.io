## 🧩 상속(Inheritance) 이해하기

객체지향 프로그래밍(OOP)에서 **상속**은 핵심 개념 중 하나입니다.  
상속은 **객체 간의 공통적인 부분을 공유**하여 코드 중복을 줄이고, 유지보수를 쉽게 만들어줍니다.  

---

## 상속의 기본 개념
- **코드 중복 방지**: 공통 기능을 부모 클래스에 두고, 자식 클래스가 이를 물려받아 사용  
- **Tree 구조**: 일반적으로 부모-자식 관계는 트리 형태를 가짐  
- **재정의(오버라이딩)**: 자식 클래스가 부모의 메서드를 재정의하여 다양성을 확보 → **다형성**  

### 예시 
```python
class Shape:
    def draw(self):
        print("네모 그리기")

class RoundedSquare(Shape):
    def draw(self):
        print("둥근 사각형 그리기")

class Triangle(Shape):
    def draw(self):
        print("삼각형 그리기")

class Circle(Shape):
    def draw(self):
        print("원형 그리기")
```
동일한 `draw()` 메서드를 사용하지만, 자식 클래스마다 다른 동작을 수행합니다.  

---

## 단일 상속과 다중 상속
- **단일 상속**: 하나의 부모 클래스만 상속  
- **다중 상속**: 여러 부모 클래스를 동시에 상속  

### MRO (Method Resolution Order)
- 다중 상속 시 메서드 탐색 순서를 결정하는 규칙  
- 파이썬은 **먼저 상속받은 클래스**를 우선 실행  
- 직접 MRO를 바꿀 수는 없지만, 상속 순서를 변경하면 간접적으로 제어 가능  

### Diamond 문제
- 다중 상속 시 동일한 메서드가 여러 경로로 상속되어 중복 문제가 발생  
- C++: 에러 발생  
- Java: 다중 상속 불가능  
- Python: MRO 규칙으로 해결  

---

## 포함(Composition) vs 상속(Inheritance)
- **is-a 관계**: 상속 (자식은 부모의 일종이다)  
- **has-a 관계**: 포함 (클래스 내부에 다른 클래스를 멤버로 포함)  

👉 상황에 따라 상속과 포함 중 적절한 구조를 선택해야 합니다.  

---

## 리스코프 치환 원칙 (Liskov Substitution Principle, LSP)
**정의**: 자식 클래스는 부모 클래스의 기능을 완전히 대체할 수 있어야 하며, 부모 클래스를 사용하는 코드가 자식 클래스로 바뀌더라도 정상적으로 동작해야 한다는 원칙.  

### 핵심 요점
- 부모 클래스 기반 설계  
- 자식 클래스 수가 늘어나도 부모 코드에 영향 없음  
- 유지보수가 쉬워짐 (부모 코드만 수정하면 됨)  
- 확장성과 안정성 확보  

### 예시
```python
class Bird:
    def fly(self):
        print("날아간다!")

class Sparrow(Bird):
    pass

class Ostrich(Bird):
    def fly(self):
        raise Exception("타조는 날 수 없습니다.")  # LSP 위반
```
Ostrich는 부모의 계약을 깨뜨리므로 LSP를 위반한 사례입니다.

## 오버로딩과 오버라이딩
- **오버로딩(Overloading)**: 같은 이름의 함수지만 매개변수 타입/개수로 구분  
- **오버라이딩(Overriding)**: 부모 메서드를 자식이 재정의  

### 연산자 오버로딩
파이썬에서는 연산자를 직접 재정의할 수 있습니다.  
- `__add__`, `__sub__`, `__mul__`, `__truediv__` 등  
- 산술, 관계, 논리, 대입 연산자 모두 오버로딩 가능  


## 순수가상함수 (Abstract Method)
- 함수의 선언만 있고 body가 없음  
- 인스턴스화 불가능 (클래스 이름 뒤에 `()` 붙여 호출 불가)  
- 자식 클래스에서 반드시 구현해야 함  


## 디자인 패턴과 상속
- **Delegate 패턴**: 클래스를 매개변수로 전달하여 기능을 위임  
- **Facade 패턴**: 여러 클래스를 감싸고, 인터페이스만 노출 → 사용자는 마지막 클래스만 접근  

✨ 상속과 디자인 패턴을 함께 활용하면 구조적이고 유지보수하기 쉬운 프로그램을 만들 수 있습니다.

## 정리
- 상속은 **코드 중복을 줄이고 유지보수를 쉽게 하는 핵심 개념**  
- 단일 상속과 다중 상속, MRO, Diamond 문제를 이해해야 함  
- **리스코프 치환 원칙(LSP)**을 지켜야 안정적인 객체지향 설계 가능  
- 오버로딩/오버라이딩, 연산자 오버로딩을 통해 다형성을 확보  
- 상속과 포함, 디자인 패턴을 적절히 활용해 확장성과 재사용성을 높일 수 있음
